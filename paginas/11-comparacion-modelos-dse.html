Comparación de modelos en el banco DSE

El mismo sistema, el mismo banco y la misma configuración, con un modelo distinto cada vez. Esta página se dibuja sola a partir de data/modelos_dse.js: cada modelo medido añade una fila y una barra, y todo lo que se ve sale de los archivos de resultados, con las huellas del sistema, del ejecutor y del banco.

Resumen

Un nivel por columna: B es una sola acción con el LLM (99 tareas), C son dos herramientas encadenadas (27), D son las tareas reales del banco, con 15 tareas de dev (3 repeticiones) y 57 de test (1 repetición). El nivel A, que son las herramientas solas contra el oráculo sin LLM, da 1914 de 1914 y no depende del modelo.

Por nivel

Porcentaje de tareas correctas. Los umbrales del banco son 90 % en selección, argumentos y fidelidad para B y 80 % de correctas para C; D no tiene umbral.

Por plantilla

Qué mide cada plantilla: T1 leer un valor, T2 elegir entre candidatos, T3 el mejor que cumple, T4 una curva, T5 un frente de Pareto, T8 reparar una configuración, T9 un caso imposible, T10 una trampa de dominio. T1 y T9 no están en dev.

Test (57 tareas, 1 repetición)

Dev (15 tareas × 3 repeticiones)

Tarea por tarea (test)

Cada tarea es una columna con un cuadro por modelo, en el mismo orden que la leyenda. Relleno = acierta, vacío = falla. Pasa el ratón para ver el nombre.

Consumo y costo

Tokens, llamadas y tiempo sumando B, C, D dev y D test. Los modelos de nube no informan el tiempo de generación, así que el tiempo es el de reloj por tarea y no es comparable con el de una GPU concreta.

Qué se lee de las dos primeras mediciones

Resultado

Un empate en nota, una diferencia enorme en fiabilidad

En el test los dos aciertan casi lo mismo (48 y 49 de 57), y con una repetición esa diferencia es ruido. Lo que sí separa a los modelos: el 9B local tuvo 8 fallos de protocolo y 8 corridas rescatadas en el test, DeepSeek ninguno, y DeepSeek termina el test en 23 minutos frente a 220.

Matiz

Más parámetros no ganan B

En el nivel B (una sola acción) DeepSeek responde mejor, con el valor correcto en 99 de 99 tareas, pero llama predecir_recursos antes de la herramienta correcta, sobre todo antes de estimar_baseline. Con el criterio estricto del puntuador eso cuenta como fallo de selección (88,9 % frente a 97,0 % del 9B). No es un error de elegir mal; es una preparación de más. Además, el sistema se afinó durante días mirando los fallos del 9B.

Abierto

T5 no se resuelve con más tamaño

Las dos plantillas más difíciles de búsqueda son T5 (frente de Pareto) y las T8 que exigen cambiar dos o más perillas. Los dos modelos fallan las mismas tareas de T5: cambian una perilla cada vez, no las combinan, y entregan puntos que no están en el frente real. Un modelo de unos 763 mil millones de parámetros no lo arregla, así que el límite puede estar en cómo el sistema plantea la búsqueda y no solo en el modelo. Hipótesis a contrastar con tareas nuevas de dev, no con el test.

Salvedad

Una repetición en el test

El test se corrió una vez por modelo. Las diferencias de pocas tareas no se pueden atribuir al modelo. T1 y T9 no existen en dev, por eso el test y el dev no son comparables entre sí: la mezcla de plantillas es distinta. Nada del sistema se cambió mirando el test.

Añadir un modelo

  1. Correr los cuatro niveles con el modelo (los comandos están en la bitácora del proyecto): correr_base.py para B y C, y correr_modelos.py con --conjunto dev --reps 3 y --conjunto test para D. Mismas opciones que los demás: --num-ctx 16384 --num-predict 2048 --razonamiento apagado --arquitectura-json.
  2. Añadir una entrada a banco_dse/base/modelos_web.json con los cuatro archivos de resultados, el color y, si hay, el costo real del panel del proveedor.
  3. Correr python -m banco_dse.base.exportar_web, que escribe banco_dse/resultados/web/modelos_dse.js.
  4. Copiar ese archivo a data/modelos_dse.js de este repositorio y publicar. La página lo lee entera: no hay que tocar el HTML.

Regla de comparación: mismo sistema (misma huella), mismo banco, mismo contexto y razonamiento apagado. Si un modelo de nube no deja apagar el razonamiento o no informa los tokens, se anota como condición distinta y no se compara de forma directa.
